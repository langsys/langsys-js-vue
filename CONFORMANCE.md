**What surfaced while re-rowing against 8.0.1** — each item came from running code rather than reading it, and only the last was prompted:

1. **Two of this binding's own documents were wrong against the core it ships with.** The README said `apiUrl` does not exist and to use `LangsysAppAPI.setBaseUrl()`; the core declares `apiUrl` and warns that `setBaseUrl()` after `init()` leaves the SDK permanently inert. README-SSR's hand-off initialized in `onMounted`, which never runs on the server, so every server render served base language while the page promised better SEO and no flash of untranslated content. Both corrected; both now pinned by tests.
2. **Server rendering leaks between requests.** Two concurrent renders, Italian and German, interleaved across one `await`, both served German (SRV-2). `<Translate>` and `<Phrase>` serve base language on the server (SRV-1), and a served `<Translate>` host carried no identity at all (MARK-1); an explicit `custom_id` is now stamped.
3. **One delegation control was vacuous and six were inflated.** GATE-5's only hit was a log message, which is really OBS-1's diagnostic. All 25 probes are now spot-checked against the sites they claim.
4. **The core exports `PHRASE_MARKER_ATTR` but not `CONTENT_BLOCK_MARKER_ATTR`**, so a binding that stamps content blocks on the server must duplicate the literal. It is cross-checked against the core's own stamp, and M17 proves the check catches drift.
5. **Every mutation this binding had ever cited lived only in commit messages and scratch scripts.** They are now one committed, re-runnable runner.
6. **Two positive controls caught mistakes of mine.** BIND-4's control stayed silent on my first example key, `apiUrl` — correctly, because the core defines it. The `init` hand-off control failed at 100 ms, which showed that "init seeds, just too late" was unproven until the round trip was made deterministic.
7. **The route measurement lacked two controls, and adding them measured a second non-capture shape.** The Reviewer relayed two harness traps from the Angular lane, each of which reads as "does not re-enter": a URL that never moves, and a read before navigation re-renders. This binding's route test guarded neither: its fake `t()` never recorded the URL, and the persistent-layout case asserted only a negative. With both controls on every case the layout verdict stands, and a second shape sits beside it: when a param-only navigation reuses the routed instance, a child that reads nothing from the route does not re-enter for the new URL.

> **`implemented` here means `n/a (pure)` evidence.** Every rule this binding owns governs an in-process property: the proxy's forwarding, the hydration latch, a rendered attribute, the order of events at hydration. A stateful contract fixture could neither prove nor disprove those, so none of them waits on it (CONF-2). Rules whose property depends on what the API answers belong to the core and are delegated.

## Route re-entry — the measurement behind HINT-4 and BIND-5

`src/route-reentry.test.ts` mounts real `vue-router` routes on a hash history in jsdom with the binding's
own `useT()`. The fake `t()` records `window.location.href` at each call, the value the core's discovery
capture reads, and `setup()` counts separate a re-created component from a cached or reused one.

Every case asserts two controls before its verdict counts: the URL moved to the new route, and a component
inside `<RouterView>` re-entered `t()` at that URL. They answer two harness traps the Angular lane measured,
each of which turns a correct binding into "does not re-enter". A memory history leaves the URL where it
was, so the page re-renders at the old URL; a read before `router.push()` settles sees no render at all.
Both traps are reproduced inline and fail the controls, and M22 and M23 apply them to the graded cases.

| Shape                                                  | plain `<RouterView>`                   | `<KeepAlive>` around `<RouterView>`         |
| ------------------------------------------------------ | -------------------------------------- | ------------------------------------------- |
| routed page, A→B                                       | re-enters at `#/b`                     | re-enters at `#/b`                          |
| routed page, B→A                                       | re-enters; `setup()` re-ran            | re-enters; `setup()` did not re-run         |
| persistent layout outside `<RouterView>`, A→B          | **does not re-enter**                  | **does not re-enter**                       |
| `computed()` over `t()` in a routed page, revisit      | re-enters; instance re-created         | **does not re-enter**; URL already captured |
| child that reads nothing from the route, `/p/1`→`/p/2` | **does not re-enter**; instance reused | **does not re-enter**; instance reused      |

KeepAlive alone does not starve the lane: the instance is cached and `t()` is re-entered anyway, because Vue
re-renders a reactivated component and templates call `t.value(…)` on every render. The gap is a component
that survives a navigation and depends on nothing that changed: a persistent layout, or a child of an
instance vue-router reuses when only a param changes. It never re-renders, so its misses belong to the first
URL only. The spec files that shape under HINT-4, and a router hook closes it without waiting for a render.

## Earlier corrections, kept on the record

**The five that were never dropped.** An earlier audit reported that replacing the enumerating wrapper
with a proxy recovered five dropped core methods. All five are `private` in the core
(`langsys-app.ts:84`, `:494`, `:513`, `:537`, `:567`), emitted as `private NAME;` in the `.d.ts`, and
never public in git history. TypeScript's `private` is erased at runtime, so a prototype walk found them
and called them lost API. Measured against the `.d.ts`: the old wrapper dropped **0 public members**.
Two measurements sharing a method share its blind spot; agreement between them is not independent
evidence.

**The casing correction.** The core's 838 line canonicalizes locales to lowercase `xx-yy` (WIRE-3), and
nine sites in this repo still taught `'en-US'`. The worst was a copy-pasteable README guard that tested
`supportedLocales.includes(detected)` against an `'en-US'` list: `detectPreferredLocale()` returns
lowercase, so every user silently got the fallback. All nine corrected.

**The hydration latch.** `useWriteEnabled` adopts the live value on a macrotask, latched on first call.
`nextTick()` would not do: a microtask still drains inside the hydration pass. It depends on the core's
TFunction identity contract (core `cd07df1`): a fresh closure per change is the change signal.

## Ranked gaps

Ranked by what each costs, not by rule order.

1. **SRV-2 — concurrent server renders serve each other's language.** A visitor gets the wrong language,
   silently and only under traffic. README-SSR now warns; the fix waits on the SRV ownership decision.
2. **SRV-1 — `<Translate>` and `<Phrase>` serve base language on the server.** Crawlers index the base
   language under a translated URL for all block and phrase content.
3. **HINT-4 — components that survive a navigation without re-rendering never report the new route.** That
   is persistent layouts, and route-independent children of an instance reused on a param-only navigation.
   Discovery is under-reported on shared chrome copy, and for those children on every param URL after the
   first. Waits on the core's navigation entry point.
4. **MARK-1 — a derived content-block id is absent from served HTML.** Server-side debugging and parity
   probes cannot see which block is which.
5. **SRV-3 and SRV-5 — no server collection and no server child capture.** Nothing discovered during a
   server render is collected by this binding.
6. **Release wave — the dependency floor still reads `^0.6.5`**, which resolves a core without 838.
7. **Delegated rows over non-green core rows.** Not work in this repo, but not proof either.
