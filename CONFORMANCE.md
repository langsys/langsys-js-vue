**What surfaced while re-rowing against 8.2.18** — each item came from running code against the contract double or the shared vectors:

1. **GATE-10's readers are the DOM hosts, and a bare `t()` is outside them.** `<Translate>` and `<Phrase>` hand the core their host, and the core's ancestor walk suppresses both lanes under a `data-ls-resolved` ancestor; `useT()` under the same ancestor registers, measured against the double. Spec 8.2.10 makes that the rule's negative control: a `t()` argument is source text the app supplies, and GATE-9 is the gate for `t()`.
2. **HINT-13's hook closes a second Vue shape.** Besides the persistent layout, vue-router reuses a route component when only a param changes, and a child of it that reads nothing from the route never re-renders. With `syncNavigation(router)` its miss is stored for the new URL; without it, nothing is.
3. **Server rendering still leaks between visitors.** Two concurrent renders in it and de both served German, because this binding reads the core's process-wide catalog. Recorded under SRV-1, SRV-2 and SRV-3; the owner of Vue server rendering is an open operator decision.
4. **The message render decision is the core's.** `useServerMessage()` is a reactive wrapper over `renderServerMessage()`; this binding reads no catalog of its own (probe p08: 0). Entries are read only from the key or resolver the app configures, beside the framework's own error body, which stays untouched — the Inertia page case asserts it.

5. **The migration config and snapshots pass through untouched.** `legacyKeys` reaches the core through the `init` override as the app wrote it: a key resolves to its source value, and a vue-i18n pipe plural renders by count only because its `format` arrived. This binding's code never names the option (probe p37: 0). A snapshot loads through the forwarded `loadSnapshot`, and a refusal reaches the caller with its reason; the core takes a snapshot through that method, not through `init`.

> **`implemented` here means `n/a (pure)` or `contract` evidence.** HINT-13 and GATE-10 turn on what the server stores, and are proven against the vendored contract double. Every other owned rule governs an in-process property — the proxy's forwarding, the hydration latch, a rendered attribute, the order of events at hydration — which the double could neither prove nor disprove. Rules whose property depends on what the API answers, and that this binding does not touch, belong to the core and are delegated.

## Route changes — HINT-4 and HINT-13

`src/navigation-contract.test.ts` is HINT-13's own Test against the contract double: a read-only session whose key may report, so the double stores a hint for any page reported to it. Page components render only phrases the catalog translates, so a hint for a page can only come from the missing phrase the case places.

| Shape                                                     | with `syncNavigation(router)` | without                                               |
| --------------------------------------------------------- | ----------------------------- | ----------------------------------------------------- |

| persistent layout, `<KeepAlive>`, A→B                     | hint stored for B             | —                                                     |
| route-independent child of a page reused on `/p/1`→`/p/2` | hint stored for `/p/2`        | —                                                     |

`src/route-reentry.test.ts` measures what Vue itself re-renders on navigation, with no hook: routed pages re-enter under a plain `<RouterView>` and under `<KeepAlive>`; a persistent layout, a `computed()` over `t()` in a cached page, and a route-independent child of a reused instance do not. ## Ranked gaps

Ranked by what each costs, not by rule order.

1. **SRV-2 — concurrent server renders serve each other's language.** A visitor gets the wrong language, silently and only under traffic. README-SSR warns; the fix waits on the SRV ownership decision.
2. **SRV-1 — `<Translate>` and `<Phrase>` serve base language on the server.** Crawlers index the base language under a translated URL for all block and phrase content.
3. **Release wave — the dependency floor reads `^0.6.5`**, a core with none of the 838 surface this binding imports.
4. **MARK-1 — a derived content-block id is absent from served HTML.** Server-side debugging and parity probes cannot see which block is which.
5. **SRV-3 and SRV-5 — no server collection and no server child capture.** Nothing discovered during a server render is collected by this binding.
6. **MSG-12 — no end-to-end Inertia redirect here.** The page half is proven; the session half lives in the server binding.
7. **Delegated rows over non-green core rows**, the core's partial rows. Not work in this repo, but not proof either.
