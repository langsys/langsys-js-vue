**What this binding has to get right** — each item is pinned by a test, on the SDK test clone wherever the property is what the API stores:

1. **GATE-10's readers are the DOM hosts, and a bare `t()` is outside them.** `<Translate>` and `<Phrase>` hand the core their host, and the core's ancestor walk suppresses both lanes under a `data-ls-resolved` ancestor; `useT()` under the same ancestor registers, as the rule's negative control requires: a `t()` argument is source text the app supplies, and GATE-9 is the gate for `t()`.
2. **HINT-13's hook covers two Vue shapes.** A persistent layout, and a child of a route component vue-router reuses when only a param changes, which never re-renders. With `syncNavigation(router)` its miss is stored for the new URL; without it, nothing is.
3. **Server rendering runs through the core's request scope.** A Nuxt plugin cannot wrap Nuxt's render, and `scope.enter()` inside an awaited async function does not isolate the request (interleaved Italian and German requests serve the Italian one German, pinned), so the Nuxt path hands the scope to the request's own Vue app with `provideRequestScope`, which needs no async context. The composables, `useServerMessage()`, `localeHeaders()` and `<Translate>`/`<Phrase>` read that scope, in components and in code Nuxt runs in the app's context; whatever asks the core renders inside it with `scope.run()`, because the core reads only the async-context scope. On the server the composables never subscribe, since Vue never stops a server component's effect scope. `npm run test:nuxt` builds `example/nuxt` with Nuxt and serves it against the SDK test clone.
4. **The message render decision is the core's.** `useServerMessage()` is a reactive wrapper over `renderServerMessage()`; this binding reads no catalog of its own (probe p08: 0). Entries are read only from the key or resolver the app configures, beside the framework's own error body, which stays untouched.

5. **The migration config and snapshots pass through untouched.** `legacyKeys` reaches the core through the `init` override as the app wrote it; this binding's code never names the option (probe p37: 0). A snapshot loads through the forwarded `loadSnapshot`, and a refusal reaches the caller with its reason.
6. **Blocks render without a DOM.** `<Translate>` and `<Phrase>` render through the core's `renderBlock` and re-attach each translated element to its original vnode through `source`, so handlers and refs survive markup the translation moved. Every block on this path hands the core its host when it registers, which claims it: one nested under an ancestor that falls back to the core's DOM class registers itself, once, and the ancestor's walk never takes it over with the ancestor's params.
7. **A variable in a compiled template is a placeholder, or nothing is registered.** `Hello {{ name }}` reaches `<Translate>` as `Hello Ana`. The compiler transform rewrites it to `%name%` and a param, on the template root, because Vue runs user transforms after its own and its server compiler copies a component's slot children when it reaches the component. Without the transform, Vue's patch flags mark the block as holding a variable: it renders from the catalog and registers nothing. Names are the core's `derivePlaceholderNames()`, so every SDK derives the same phrase. A value printed inside an author's exclusion (`translate="no"`, `data-notrans`, `<DontTranslate>`) is no part of the sentence: the transform marks it with VAR-3's attribute form, so a block stores its name and a phrase keys `{m0o}{m0c}`.

## Route changes — HINT-4 and HINT-13

## Ranked gaps

Ranked by what each costs, not by rule order.

1. **Hand-written render functions and JSX register their values.** They carry no compiler signal; the README tells them to write `%name%` and params.
2. **Without the compiler transform, a block holding a variable registers nothing.** It renders only what the catalog already holds; the transform is one line of build config, and the core's debug notice names it.
3. **A block whose slot holds a component or `v-html` is served as source.** The sanctioned fallback: translated after mount. Crawlers see source for exactly those blocks.
